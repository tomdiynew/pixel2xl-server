Pixel 2 XL 变小服务器：刷机与搭建全记录

Google Pixel 2 XL（taimen / 骁龙 835）· Android 11 → LineageOS 22.2（Android 15）+ Magisk + Termux · 2026-10-17

0概览

目标和红米那台相同：常年插电、能上网、屏幕正常显示的局域网小服务器，开机画面也做成同样的风格。

功能说明
系统LineageOS 22.2（Android 15，安全补丁 2026-10），官方 nightly 版
rootMagisk v30.7
远程登录ssh -p 8022 192.168.43.202（Termux，密钥登录）
状态网页http://192.168.43.202:8080
电池保护保持在 50%–60%
开机界面自定义开机动画（图片 + 进度条 + 声音）、开机后 Termux 自动演示

设备信息

项目值
型号 / 代号Pixel 2 XL / taimen（和 Pixel 2 walleye 共用 wahoo 源码）
芯片 / 内存 / 存储骁龙 835 / 4 GB / 64 GB
屏幕1440 × 2880（18:9）
原系统Android 11 RP1A.201005.004.A1（Google 最后一个官方版本）

命令前的标签：MAC Mac 终端；ADB 手机系统里（adb shell）；RECOVERY 手机在 LineageOS Recovery 时；TERMUX 手机的 Termux 里。

1和红米的区别

红米 Note 2（Android 7）Pixel 2 XL（Android 15）
SELinux宽松模式（permissive）强制模式（enforcing）：自己加的系统服务会被拒绝
系统分区直接可写只读，有完整性校验；改动要用 adb remount
后台服务自定义 init 服务Magisk 的 service.d 开机脚本
充电控制/proc/mtk_battery_cmd/current_cmdbattery/charging_enabled（骁龙标准接口）
开机动画位置/system/media/product/media
开机第一屏logo 分区，可以改写在带签名的 bootloader 里，改不了（见第 15 节）
开机声音放进动画包就能响要额外补一条 SELinux 规则（见第 13 节）

2检查能否解锁

ADB 
adb shell getprop ro.product.device         # taimen
adb shell getprop ro.oem_unlock_supported   # 1 = 支持 OEM 解锁
adb shell getprop ro.boot.cid               # 00000000 = Google 商店版；VZW__001 = Verizon 版（锁死）
adb shell getprop ro.build.display.id       # RP1A.201005.004.A1 = Android 11 最终版
adb shell getprop sys.oem_unlock_allowed    # 开发者选项里"OEM 解锁"打开后变成 1
  • 最关键的是 cid：Verizon 运营商版的 bootloader 锁死，无法刷机。
  • LineageOS 要求底层固件是 Android 11 最新版，这台出厂停在这一版，正好满足。
  • 在手机上打开 OEM 解锁：设置 → 关于手机 → 连点"版本号"7 次 → 设置 → 系统 → 开发者选项 → OEM 解锁。这个开关需要手机联网才能打开。

3下载并校验

MAC 
curl -s https://download.lineageos.org/api/v2/devices/taimen/builds | jq '.[0].files[] | {filename, sha256, url}'
  • LineageOS 官方 API 会列出最新版本的所有文件、下载地址和 SHA256。这次用的是 20261015 nightly。
  • 只需要两个文件：lineage-22.2-…-taimen-signed.zip（刷机包，969 MB）和 boot.img（LineageOS Recovery，40 MB）。
D=/Volumes/SSD1G/download/pixel2xl-lineage; mkdir -p $D; cd $D
curl -fLO https://mirrorbits.lineageos.org/full/taimen/20261015/lineage-22.2-20261015-nightly-taimen-signed.zip
curl -fLO https://mirrorbits.lineageos.org/full/taimen/20261015/boot.img
shasum -a 256 -c files.sha256          # 每行 "sha256  文件名"，来自上面的 API

4解锁 bootloader

会清空手机所有数据。先备份，并在手机设置里退出 Google 账号。
MAC 
adb -d reboot bootloader     # 重启到 bootloader（或关机后按住 音量下 + 电源）
fastboot getvar all          # is_oem_unlocked: yes / unlocked: no / version-bootloader: TMZ30m
fastboot flashing unlock     # 手机上会弹出确认界面
  1. 手机显示 "Unlock the bootloader?"：先按 音量键 选到 Unlock the bootloader，再按 电源键。
  2. 界面底部 "Device state" 变成 unlocked 就成功了。
坑 1：第一次直接按了电源键，默认选中的是"不解锁"，返回 Set device unlocked! canceled，手机没有变化，重新执行一次即可。
坑 2：解锁成功后，fastboot getvar unlocked 仍然显示 no，要重启一次才会刷新。以屏幕上显示的 "Device state" 为准。

5刷 LineageOS Recovery

MAC 
fastboot flash boot boot.img      # 写入当前槽位（boot_b）
  • Pixel 2 XL 没有独立的 recovery 分区，recovery 在 boot 镜像里，所以刷的是 boot。
  • 如果 bootloader 没解锁，这一步会被直接拒绝，所以它也能顺便验证解锁是否成功。

进入 Recovery：这台的 bootloader 不响应 fastboot reboot recovery，要在 bootloader 界面用 音量键 选 Recovery mode，再按 电源键。

6安装 LineageOS 22.2

  1. Recovery 里选 Factory reset → Format data / factory reset，清掉原来 Android 11 的加密数据。
  2. 回主菜单，选 Apply update → Apply from ADB。
RECOVERY 
adb -d sideload lineage-22.2-20261015-nightly-taimen-signed.zip
  • sideload：Mac 一边传，手机一边安装。手机端会校验 LineageOS 的官方签名。
  • 装完后，adb 有时会一直不退出或显示 47%，这是正常现象，以手机屏幕上的提示为准。
  1. 提示 "to install additional packages, you need to reboot recovery first" 时选 No（不装 Google 应用）。
  2. 选 Reboot system now。第一次开机可能要几分钟。

7首次开机

新系统默认关闭了 USB 调试。打开方法：设置 → 关于手机 → 滑到底部，连点 "版本号"（不是"Android 版本"）7 次 → 设置 → 系统 → 开发者选项 → USB 调试。

ADB 
adb shell getprop ro.lineage.version              # 22.2-20261015-NIGHTLY-taimen
adb shell getprop ro.build.version.security_patch # 2026-10-01
adb shell getprop ro.boot.slot_suffix             # _a：刷机包装到了另一个槽位
adb shell getprop ro.boot.verifiedbootstate       # orange = bootloader 已解锁
开机警告：以后每次开机都会先出现橙色的"bootloader 已解锁"警告页，几秒后自动继续。这是 Google 的固定提示，去不掉。
坑：插着 USB 但 adb 看不到手机。刚打开 USB 调试时，USB 连接没有刷新。拔掉线重新插上，手机弹出"允许 USB 调试吗？"后点允许。

8安装 Magisk（root）

LineageOS 是 userdebug 版本，插 USB 时可以用 adb root。但要让后台服务开机自动以 root 运行，需要 Magisk。这次没有用 Magisk 应用的图形界面，而是在命令行里修补 boot。

MAC 
curl -fLO https://github.com/topjohnwu/Magisk/releases/download/v30.7/Magisk-v30.7.apk
adb root
adb exec-out 'dd if=/dev/block/by-name/boot_a bs=1048576' > backup/boot_a-stock-lineage.img   # 先备份
  • 导出的 boot_a 和官方下载的 boot.img md5 完全一致，说明手机上用的就是这个版本。
MAC 
# 从 APK 里取出修补工具：lib/arm64-v8a/libXXX.so 改名为 XXX，加上 assets 里的脚本
unzip Magisk-v30.7.apk 'lib/arm64-v8a/*' assets/boot_patch.sh assets/util_functions.sh assets/stub.apk
for n in magiskboot magiskinit magisk init-ld busybox magiskpolicy; do cp lib/arm64-v8a/lib$n.so out/$n; done
adb push out/. /data/local/tmp/mg/
adb push backup/boot_a-stock-lineage.img /data/local/tmp/mg/boot.img
ADB 
cd /data/local/tmp/mg && chmod 755 *
KEEPVERITY=false KEEPFORCEENCRYPT=true ./busybox sh boot_patch.sh boot.img   # 生成 new-boot.img
  • boot_patch.sh 就是 Magisk 应用"修补文件"时运行的脚本。
  • KEEPVERITY=false：关闭分区完整性校验。后面用 adb remount 改写系统分区需要这一项。
MAC 
adb pull /data/local/tmp/mg/new-boot.img boot_a-magisk-v30.7.img
adb reboot bootloader
fastboot flash boot_a boot_a-magisk-v30.7.img
fastboot reboot
adb install -r Magisk-v30.7.apk

8.1 补齐 Magisk 运行文件（关键）

ADB 
cd /data/local/tmp/mg
cp busybox magisk magiskboot magiskinit magiskpolicy init-ld util_functions.sh boot_patch.sh stub.apk /data/adb/magisk/
chmod 755 /data/adb/magisk/*
坑：用命令行修补时，没有人往 /data/adb/magisk 里放运行工具。正常情况下这一步由 Magisk 应用完成。少了这些工具，Magisk 每次开机只执行最后的 "boot-complete" 阶段，开机脚本和模块全部被跳过，也不会报错。日志里只有 boot-complete triggered 一行就是这个症状。

9Termux 与 SSH

MAC 
adb install -r com.termux_1002.apk             # F-Droid 版 Termux 0.118.3
adb shell pm list packages -U com.termux       # uid:10207
adb shell am start -n com.termux/.app.TermuxActivity   # 首次打开，解压基础环境

9.1 以 Termux 用户身份执行命令

ADB 
/debug_ramdisk/su 10207 -g 10207 -G 3003 -c 'PREFIX=… HOME=… PATH=$PREFIX/bin:/system/bin …; 命令'
  • /debug_ramdisk/su：Magisk 的 su。adb root 的命令搜索路径里没有它，要写完整路径。
  • 10207：切换到 Termux 的用户。
  • -G 3003：加入 inet 组。Android 只允许这个组的进程联网。
  • -g 10207：必须写。没有 -g 时，-G 的第一个组会被当成主组。漏写这一项时，命令曾经卡住不动。
TERMUX 
pkg update -y && pkg install -y openssh python jq neofetch procps
sshd                                  # 端口 8022
MAC 
ssh -p 8022 192.168.43.202

9.2 SELinux 标签问题

坑：通过 Magisk su 安装的文件标签是 app_data_file:s0，少了 Termux 专属的分类 c207,c256,c512,c768。Termux 应用运行在普通应用的权限域里，读不了这些文件，于是报错 CANNOT LINK … libncursesw.so.6 not found。而 SSH 跑在 Magisk 的权限域里，一切正常，所以这个问题很隐蔽。
ADB 
chcon -R -h u:object_r:app_data_file:s0:c207,c256,c512,c768 /data/data/com.termux/files
  • -h 不能省：不加的话，只会改符号链接指向的文件，链接本身的标签不变，libncursesw.so.6 这个链接仍然读不了。
  • 这条命令已经写进守护服务，每次开机都会执行一次。

11充电限制 50–60%

ADB 
echo 0 > /sys/class/power_supply/battery/charging_enabled   # 停止给电池充电，USB 继续给手机供电
echo 1 > /sys/class/power_supply/battery/charging_enabled   # 恢复充电
cat /sys/class/power_supply/battery/status                  # Not charging / Charging
坑：开机后，系统的充电服务会把 charging_enabled 改回 1。重新插拔 USB 时也会。
解决：phonectl.sh 每 15 秒核对一次，被改回就重新写入，并记录日志：charging_enabled was reset by the system; re-applied 0。

日志：/data/adb/pixelsrv/phonectl.log。修改区间：在 /data/adb/pixelsrv/phonectl.conf 里写 CHARGE_LOW=…、CHARGE_HIGH=…。

12开机动画

MAC 
W=1440 H=2880 tools/build_bootanim.sh assets/images/bootanim-v2-portrait.png \
    /Volumes/SSD1G/download/pixel2xl-lineage/bootanimation-pixel.zip assets/audio/phone_boot.mp3
./deploy.sh bootanim
  • W=1440 H=2880：Pixel 的屏幕是 18:9，比图片更瘦长。脚本会按宽度缩放图片，上下补黑边，进度条按比例放大并放在底部。
  • deploy.sh bootanim：先备份原版，然后 adb remount，直接写入 /system/product/media/bootanimation.zip。
  • bootanimation-dark.zip 是指向 bootanimation.zip 的链接。LineageOS 在深色主题下播放 dark 版，两个都会生效。
坑：Magisk 模块替换不了开机动画。开机动画在开机第 4.5 秒左右就启动了，比 /data 分区挂载还早，而 Magisk 模块要等 /data 准备好后才挂载。开机完成后再去检查，看到的确实是替换后的文件，但开机动画读文件时还是原版。日志显示播放的是 …/part2，而我们的包里只有 part0 和 part1，这就是破绽。
解决：改用 adb remount 直接写入系统分区。

13开机声音

声音文件 audio.wav 放在动画包的 part0 里，但在 Pixel 上一开始完全不响。排查过程：

  1. 开机时实时记录日志（开机阶段日志量太大，事后看会缺条目）。日志显示：found audio.wav → Audio service is not ready yet → cannot play clip without a player。
  2. 同一时刻，用 service check audio 查询，服务明明已经存在。
  3. 内核日志找到真正的原因：avc: denied { find } … name=audio scontext=u:r:bootanim:s0 tcontext=u:object_r:audio_service:s0。SELinux 不允许开机动画进程查询 audio 服务，所以它永远认为音频服务没准备好。原版 LineageOS 22.2 在这台手机上本来就放不了开机声音。
ADB 
# magisk/bootsound.sh 的核心（在 Magisk 最早的 post-fs-data 阶段运行）
/data/adb/magisk/magiskpolicy --live "allow bootanim audio_service service_manager find"
# 等 audio 服务出现，并且开机动画还在播放，就重启开机动画一次
service check audio | grep -q ": found" && setprop ctl.restart bootanim
  • magiskpolicy --live：在运行中的 SELinux 策略里加一条规则，只允许开机动画查询 audio 服务，不放开其他权限。
  • 重启开机动画：第一次启动时 audio 服务还不存在，重启后的开机动画才能查到它，并创建播放器。
当前状态：日志显示声音已经正常播放（Created buffer queue player → playClip → 11.6 秒后 destroying audio player），音乐和进度条同时开始。代价：创建播放器要等大约 10 秒，这段时间画面会停住，整个开机过程约 34 秒。还没确认：耳朵实际能否听到。bootsound.sh 里仍然开着实时日志记录（/data/adb/pixelsrv/bootanim-live.log），确认后可以关掉。
走过的弯路：用 Termux 的 play-audio 以 root 身份播放，进程启动了，但听不到声音，而且不会自己退出。用系统音乐播放器 Twelve 手动播放 /sdcard/Download/phone_boot.mp3 能听到，说明扬声器和音量都正常。

14开机 Termux 演示

和红米相同的演示脚本（termux/bin/boot-intro）：逐字"敲出"常用命令 → 真实连接 Claude、Gemini、OpenAI 的 API 服务器 → 7 项状态面板。提示符根据机型自动显示 laohan@pixel。

ADB 
# Android 8 以后不允许在后台直接启动其他应用的服务，要用 start-foreground-service
am start-foreground-service --user 0 -n com.termux/com.termux.app.RunCommandService \
  -a com.termux.RUN_COMMAND --es com.termux.RUN_COMMAND_PATH /data/data/com.termux/files/home/bin/boot-intro \
  --ez com.termux.RUN_COMMAND_BACKGROUND false
locksettings set-disabled true      # 关闭锁屏，否则 Termux 被挡住
坑：状态面板显示"SSH 未运行"，其实 SSH 一直正常。sshd 运行在 Magisk 的权限域里，Termux 应用运行在 untrusted_app 权限域里。虽然是同一个用户，SELinux 也不允许查看对方的进程，所以 pgrep 找不到 sshd。
解决：改为直接连接 8022 端口来检测：bash -c "exec 3<>/dev/tcp/127.0.0.1/8022"。

15第一屏为什么改不了

ADB 
ls /dev/block/by-name/ | sed 's/_[ab]$//' | sort -u     # 没有 logo、splash 这类分区
  • 开机的 Google 标志和"已解锁"警告页，是 bootloader（abl、xbl）自己画的，图片打包在 bootloader 程序里。
  • 手机芯片里熔断写入了 Google 的签名公钥，开机时会验证 bootloader 的签名。改动一个字节，签名就对不上，手机无法开机，而且很难救回来。
  • 自己编译整个系统也没用：Android 源码里没有 bootloader，Google 只提供编译好的文件。
  • 红米能改，是因为联发科把 logo 放在一个独立的、不检查签名的分区里。
  • 唯一能动的：用自己的密钥签名系统并重新锁上 bootloader，可以把橙色警告换成黄色提示，但同样去不掉，而且有变砖风险，不值得。
